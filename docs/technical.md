# Техническая инструкция

Поддерживаемые системы: macOS, Linux и Windows. Требуется Python 3.11+.
Основной код: `scraper/runner.py` и папки источников `scraper/consultantplus/`,
`scraper/sudact/`. Общие настройки и хранение результатов — в `scraper_common/`,
интерфейсы — в `interfaces/cli.py` и `interfaces/web/`.

## Установка и запуск

macOS / Linux:

```bash
python3 install.py
.venv/bin/python -m interfaces.cli --config config.toml
.venv/bin/python -m interfaces.web.app
```

Windows PowerShell:

```powershell
py -3 install.py
.\.venv\Scripts\python.exe -m interfaces.cli --config config.toml
.\.venv\Scripts\python.exe -m interfaces.web.app
```

Установщик определяет ОС, создаёт или проверяет `.venv`, устанавливает приложение
и Chromium, выполняет проверку импорта и запуска браузера. На Windows он также
проверяет наличие Tkinter для выбора папки. На Linux системные зависимости
устанавливаются через Playwright `--with-deps`; Tkinter может потребовать
отдельного пакета `python3-tk`. Существующий конфиг сохраняется. Несовместимое
окружение переносится в `.venv.backup-*`.

Windows-оболочки:

- `install-windows.bat` — установка; ищет Python 3.11+ через `py` или `python`.
- `start-windows.bat` — GUI, с сохранением кода завершения процесса.
- `scrape-windows.bat --config config.toml --debug` — CLI из терминала.
- `test-windows.bat` — отдельное окружение `.venv-windows-tests` и весь набор тестов.

Файлы `.bat` используют CRLF и UTF-8, задают `PYTHONUTF8=1`. Настройки окончаний
строк находятся в `.gitattributes`. Фоновые процессы GUI и выбора папки дополнительно
запускаются с `-X utf8`: JSON, запросы и пути с кириллицей не зависят от кодировки ОС.

CLI принимает `--debug` (отладка выключена по умолчанию), `--http`/`--no-http`
(HTTP включён по умолчанию). Папка результатов берётся из `export.directory`;
относительный путь считается от папки конфига. На Windows в TOML удобно использовать
прямые слеши: `C:/Users/Name/Documents`. Пути с пробелами в командной строке
заключайте в кавычки. Каждый источник получает новую сессию; авторизацией и выходом
управляет его адаптер.

Веб-сервер слушает `127.0.0.1`. На Windows папка результатов открывается через
`os.startfile`, диалог выбора — через Tkinter в отдельном главном потоке процесса.
Для остановки парсеру передаётся команда через stdin; принудительное уничтожение
процесса может не выполнить выход из источника. Блокировка запуска проверяет PID
через Windows API, не посылая сигнал завершения процессу.

## Источники и результаты

Настройки смотрите в `config.example.toml`. `scraper.sources` задаёт порядок запуска.
Нереализованные источники пропускаются. Пока работает только К+, раздел высших
судов; sudact.ru — заглушка. Полный обход подразделов и страниц списков не реализован.

В выбранном каталоге лежат общая `судакты.csv` и индекс `.kplusplus.sqlite3`.
DOCX сохраняются в подпапках источников. Колонка «Источник парсинга» получает название
из `sources.<id>.name`. Повторная выгрузка пропускает сохранённые акты;
`export.overwrite = true` обновляет их без копий. Индекс фиксирует прогресс по одному
документу и восстанавливает CSV после сбоя. Поддерживается импорт старых таблиц и
перенос документов из корня в подпапку источника. Открытый в Excel CSV на Windows
может блокировать запись — закройте таблицу и повторите запуск.

DOCX содержит текст и абзацы без исходного оформления. HTTP-режим сверяет ответ
с браузерным текстом и использует браузер при несовпадении. Ускорение пока не
заявляется. Значения реквизитов скрываются в логах.

## Тесты без реквизитов

```bash
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest -q
```

На Windows используйте `.\.venv\Scripts\python.exe`.
Тесты не читают личный `config.toml`; реальные переменные реквизитов удаляются
из окружения тестов. Для проверок авторизации используются подставные ответы.

`tests/fixtures/consultantplus/` содержит текст решения и поля справки из реальной
локальной выгрузки: имя заявителя заменено, параметры сессии из URL удалены.
Cookies, реквизитов и состояния браузера в примерах нет. Описание происхождения
и ограничений — в README этой папки.

Обычные тесты проверяют полный сохранённый текст, справку, DOCX/CSV, HTTP-получение,
пропуски, восстановление, пути и протоколы процессов с кириллицей:

```bash
.venv/bin/python -m pytest tests/test_recorded_consultantplus.py -q
.venv/bin/python -m pytest tests/test_process_interfaces.py -q
```

HTML в примерах восстанавливает минимальный интерфейс вокруг сохранённого текста.
Это не точный снимок HTML сайта. Браузерное воспроизведение перехватывает запросы,
возвращает локальные файлы и включает offline-режим:

```bash
SCRAPER_OFFLINE_BROWSER_TESTS=1 .venv/bin/python -m pytest tests/offline -q
SCRAPER_GUI_TESTS=1 .venv/bin/python -m pytest tests/gui -q
```

В PowerShell переменные задаются отдельно:

```powershell
$env:SCRAPER_OFFLINE_BROWSER_TESTS = "1"
$env:SCRAPER_GUI_TESTS = "1"
.\.venv\Scripts\python.exe -m pytest tests/offline tests/gui -q
```

GUI-тесты запускают настоящий локальный HTTP-сервер и Chromium, но используют
подставной источник. Проверяются форма, папка, переключатели, продолжение выгрузки
и остановка. Системные диалоги выбора и открытия папки подменены; их реальную
работу нужно дополнительно проверить вручную. Вход в живой К+ не выполняется.

## GitHub Actions

Единый workflow `.github/workflows/tests.yml` выполняет установки и проверки
на Ubuntu, macOS и Windows. Он использует установщик приложения, запускает обычные
тесты, локальное воспроизведение выдачи в Chromium и тесты GUI. Действительные
логин/пароль и GitHub Secrets не нужны. Интернет нужен только для установки
инструментов и зависимостей; содержимое К+ берётся из файлов репозитория.

Запуск — после push в `main`, pull request или вручную в GitHub Actions.
Отчёты и скриншоты сохраняются в артефакты `test-reports-Linux`, `test-reports-macOS`
и `test-reports-Windows`. Проверки не подтверждают актуальность интерфейса
живого сайта: точных сохранённых HTML-ответов поиска и списка практики пока нет.
