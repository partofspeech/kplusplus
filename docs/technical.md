# Техническая инструкция (macOS и Linux)

Основной код: `scraper/runner.py` и папки источников `scraper/consultantplus/`,
`scraper/sudact/`. Общие настройки и хранение результатов — в `scraper_common/`,
интерфейсы — в `interfaces/cli.py` и `interfaces/web/`.

## Установка и запуск

```bash
python3 install.py
.venv/bin/python -m interfaces.cli --config config.toml
.venv/bin/python -m interfaces.web.app
```

CLI принимает `--debug` (отладка выключена по умолчанию), `--http`/`--no-http`
(HTTP включён по умолчанию). Папка результатов берётся из `export.directory`;
относительный путь считается от папки конфига. Каждый источник получает новую
сессию; авторизацией и выходом управляет его адаптер.

## Источники и результаты

Настройки смотрите в `config.example.toml`. `scraper.sources` задаёт порядок
запуска. Нереализованные источники пропускаются. Пока работает только К+,
раздел высших судов; sudact.ru — заглушка. Полный обход подразделов и страниц
списков ещё не реализован.

В выбранном каталоге лежат общая `судакты.csv` и индекс `.kplusplus.sqlite3`.
DOCX сохраняются в подпапках источников. Колонка «Источник парсинга» получает
название из `sources.<id>.name`. Повторная выгрузка пропускает сохранённые акты;
`export.overwrite = true` обновляет их без копий. Индекс фиксирует прогресс по
одному документу и восстанавливает CSV после сбоя. Поддерживается импорт старых
таблиц и перенос документов из корня в подпапку источника.

DOCX содержит текст и абзацы, без исходного оформления. HTTP-режим пока сверяет
ответ с браузерным текстом и использует браузер при несовпадении. Ускорение
пока не заявляется. Учётные данные скрываются в логах.

## Проверки

```bash
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest -q
```

Тесты используют подставные ответы и не проверяют реальный вход в К+.
Для штатной остановки CLI нажмите Ctrl+C; приложение попытается завершить
сессию. Принудительное уничтожение процесса не позволяет выполнить выход.
